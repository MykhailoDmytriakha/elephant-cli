# Идеи и варианты на будущее

Guide (`elephant-guide.md`) держит только принятое — реализованное или чётко сформулированное. Всё «может быть, когда-нибудь» лежит здесь и переезжает в guide только после решения владельца. Идея, от которой отказались, не стирается — помечается отклонённой, с причиной.

## Открытые

- **Волны против линейных фаз** *(поднято агентом в ретро 2026-08-23, решение за владельцем)*. Многоволновая работа (волна 2 → волна 3 → контрфактика волны 4) — это несколько полных циклов «план → работа → проверка» внутри ОДНОЙ задачи, а модель фаз линейна и одна на задачу. Отсюда расхождение: фаза показывает последнюю точку размышления, а следы уходят до проверки. Сделано пока мягко (2026-08-23): витрина и `el status` показывают фазу по следам и называют расхождение вслух; фаза для гейтов по-прежнему меняется только словом `el forward`. Нерешённое: давать ли волне собственный под-цикл фаз (тогда фаза становится парой «волна · этап»), или признать в guide, что при волновой работе фаза = где думаем, и этого достаточно.
- **Два голоса в выводе** *(поднято агентом в ретро 2026-08-23)*. На одном экране соседствуют русские подписи и английские how/cmd-блоки (`PHASE_MAP["how"]` писался для агента). Читается как два голоса. Выбрать один язык вывода — правка сквозная, поэтому решение владельца.
- **Фаза целиком по следам** *(2026-08-23)*. Сейчас `phase_reached` только ПОКАЗЫВАЕТ. Если сделать её источником истины и для гейтов, «фаза — вычислимое поле» станет буквальным, но исчезнет смысл `el forward` как остановки с причиной. Не решено.
- **Запись в маркер `.elephant`** *(2026-08-20)*. Сейчас маркер — пустой файл-знак. Идея: со временем что-то в него записывать (например, настройки хранилища или версию схемы). Что именно и зачем — не решено; расширение файла появится тогда же, если появится содержимое.
- **Галочка валидации прямо на странице** *(2026-08-20, хотел владелец)*. Страница с диска писать в файлы не может — браузеры запрещают, и File System Access API на file:// не работает. Если захочется: локальный мини-сервис `el ui` (stdlib, автозапуск через launchd) — страница на localhost умеет и читать живьём, и писать; права сохраняются (страница = рука человека). Пока приёмка — словом агенту или командой.

## Решённые (для истории выбора)

- **`el accept --close` — целиком или никак** *(2026-08-24, отзыв агента Copilot из Member_Liability_Estimator: слово записалось, затем «НЕ ЗАКРОЮ … критерии без вердикта», узел открыт, rc 1 — флаг обещал больше, чем делал)*. Стало: `plan_done(dry=True)` прогоняет все отказы, ничего не трогая, и `accept --close` зовёт его ДО записи слова; при «нет» слово не пишется, отказ перечисляет критерии и возвращает ту же команду без `--close`. Проверка остановки (слово после узла) в сухом прогоне пропускается — это слово и пишется следом. Отклонено: «слово владельца закрывает критерии как одобренные» — это пятый вердикт-пропуск, который владелец уже отверг (skip, 2026-08-20); критерии — измерение агента, слово — над ним, не вместо.
- **Указатель `--covered-by` вместо `--declined` для «докажется ниже по течению»** *(2026-08-24, тот же отзыв: WP1/WP2 проверяются сквозным прогоном в WP4/WP5, а единственная дверь — `--declined`, CLI печатал «снят» над живой работой, связь жила в тексте десяти причин)*. Не пятый вердикт, а указатель: в леджере `- [>] N.` с `→ S1.WP4[.k] · почему`; вердикт вычисляется при чтении (`validate.resolve_verdicts`) — критерий = вердикт цели (узел целиком читается по закону матрёшки: любой failed → failed; все met/declined → met; все declined → declined; иначе — долг «ждёт S1.WP4», считается как `unverified`). Долг уезжает: `plan done` закрывает узел и называет адрес, выход из validate держит; отметил цель — разрешилось само. Отказы: нет цели с критериями · сам себя · круг · без `--why`. Хранится только сырой файл (`validation_parse`), все читатели получают разрешённые вердикты через `validation_state`/`rollup` — ни один экран не пришлось учить новому слову. Отклонено: `--deferred-to` как отдельный статус со своим счётчиком — тогда каждый потребитель шести счётчиков учится седьмому; и копировать вердикт цели в файл — копия расходится.
- **`el next` по графу, `el status` в два чтения** *(2026-08-24, тот же отзыв: после закрытого WP3 `next` предлагал начать WP1 — первый открытый по id; `status` показывал 3/8 plan и отдельно «следы ушли до 5/8»)*. `plan.ready_nodes` — открытые листья с закрытыми предпосылками в порядке волн (те же `deps`, что рисуют plan.md; parked считается закрытым), `ready_line` — одна строка для `next` и `plan done` с причиной («после S1 — закрыты» / «S1.WP4 ждёт S1.WP1»), плюс строка «граф: готовы … · ждут X ← Y». `status`: полоска фаз с `~` для фаз, куда дошли следы без объявления, и две строки «объявлено N/8 — правит гейтами» / «по следам M/8 — узлов закрыто a/b · вердиктов c/d»; при исполнении из-под незакрытого плана — прямое «закрой план», иначе — «волна внутри исполнения». Открытый вопрос «волны против фаз» выше не закрыт этим — это только подача.
- **`el validate` никогда не пустой экран** *(2026-08-24, тот же отзыв: голый `el validate` «вернул пустой экран вместо леджера, help или ошибки»)*. Воспроизвести не удалось; две найденные дыры закрыты. (1) «Проверять нечего» уходило в stderr с rc 1 — теперь это экран в stdout, rc 0: из чего леджер состоит, почему пуст, какой вызов его наполнит. (2) Экран печатается до рендера страниц, а stdout при пайпе буферизуется — harness, убивший процесс по таймауту посреди `flush_renders`, унёс бы буфер с экраном; `main()` теперь делает `sys.stdout.flush()` перед рендером. Полный `el help` при этом подрос до бюджета экрана (24 000 символов) — строки карты ужаты, чтобы предупреждение о длинном выводе не появлялось на самой карте команд.
- **Флаг между словами — `el plan set s1 sync --replace "…"`** *(2026-08-24, отзыв агента Claude Code из Pero: «sync не принимает значение ни в одной форме, печатает текст обратно, поле ✗»)*. Причина не в `sync`: argparse читает `words` (nargs="*") одним глотком до первого флага, а всё после `--replace` — «unrecognized arguments: <текст>», rc 2, ничего не записано; эхо текста и читалось как успех. Стало: `main._hoist_options` перед разбором переносит известные (под)команде флаги с их значениями вперёд, слова остаются по порядку — флаг можно ставить где угодно, во всех командах и во вложенных (`context qa … --area`); незнакомый `--флаг` остаётся на месте и падает громко, а не уходит в поле текстом. Дифф-тест 841 шаг: различие только в новом шаге. Отклонено: `parse_intermixed_args` (не работает с subparsers).
- **Долг владельца — `el owe`** *(решено владельцем 2026-08-24: «вопросы, которые пользователь и сам не знает — надо выяснить; это реальность жизни»)*. Рождается на любой фазе; **не тормоз сам по себе** — держит только то, к чему привязан (`--holds node:|fork:|phase:`, `el plan block <узел> --owe n`), там СТОИМ; `el owe answer n` отпускает узел сам; `--how` обязателен; занять такой ответ под автономией нельзя; `completed` с открытым долгом — отказ. Леджер из журнала (`owe`·`owe-holds`·`owe-paid`·`owe-drop`), `owed.md` — проекция; секция «За тобой» второй на странице, бейдж на обеих витринах. Отклонено: жёсткий стоп на границе контекста (половина таких вопросов не понадобится) · хранить в `questions.md` парами (ответа нет — это не пара, и живёт не только на контексте).

- **Автономия = кредит слова · листок brief.md · поисковая задача** *(решено владельцем 2026-08-22 за четыре захода синхронизации)*. Закон: слово человека не отменяется и не подменяется — занимается в долг и записывается как долг (тот же закон, что у поправок и журнала). Механика: `el grant "<его слова>" [--until] [--no]` — событие; `--assumed "<почему>"` у `el accept` / `el context qa` / `el think decide` (+ `--undo`) — событие `assume` и пометка в файле; гейты читают файлы как раньше, займ пишется только под грантом (`autonomy.guard`); `el review`/`el debt` — леджер; платит его слово над той же областью (`--for context` покрывает все займы контекста); `completed` с долгом — отказ; последнее слово (`--for final`) не занимают; `el halt "<почему · что нужно>"` — «мой кредит дальше не распространяется», не «done»; новый `el grant` («продолжай») снимает. Печать: `el`, `el status`, `el next` — автономия первой. Листок: `brief.md` в корне задачи, `el brief` (показать / заменить целиком), лимит 20 строк / 1500 символов (`BRIEF_LINES/BRIEF_CHARS`), печатается первым в `el` и `el status`; ориентиры и указатели, не состояние (чтобы не стать второй копией — его же принцип). Поиск: без `el target` и без `--measure` (отклонены им: цель — в запросе и ИФР, числа — в критериях S2, baseline — результат S1, замеры — результат узла словами; CLI не считает «лучшее»); гигиена петли: `el plan new` отказывает на повтор имени среди соседей (--force), `el plan done` без результата в автономии — отказ, `el status` под автономией считает «пульс» (следов с прошлого взгляда, через `metadata/<task>.pulse.json`) и ругается на холостой ход. Отклонено: `el goal` с кодом выхода (судья /goal читает разговор, а не коды — состояние печатается в `el status`); тип задачи/проекта «loop/autonomous» (ярлык врёт — два записанных факта, грант и цель, из которых всё выводится); бюджет в гранте как правило (люди дают задачи словами; сроком становится человек — `--until` остался как опция); отдельный `el reject` (его «нет» — то же слово `el accept` + поправка). Тексты закона — `protocol.AUTONOMY_RULES/SEARCH_RULES`, экраны `el blueprint autonomy|search`, модуль `cli/el/autonomy.py`.
- **Рука: задача в руке = событие `hold`, пустая рука = idle** *(решено владельцем 2026-08-22 — его идея «el done снимает задачу с руки, el/el status честно говорят, что задачи нет»; подтверждена отзывом агента того же дня по коду)*. Было: «текущая» = свежайший журнал по mtime среди открытых с откатом на все — после закрытия последней открытой текущей становилась ЗАКРЫТАЯ (которую `el use` выбрать отказывается), а любая запись в чужую задачу (`el log --task`, заметка spawn в родителя) крала руку; держалось на двух ручных заплатках (`touch` обратно в spawn и в log), третья команда забыла бы. Стало: руку двигает только событие `hold` в журнале задачи — пишут его `el use`, рождение (`el new`/`el boot`), `el reopen`; spawn рождает задачу БЕЗ hold (родитель остаётся в руке структурно); в руке — задача с последним `hold` во всём хранилище, а если она закрыта — рука пуста (idle): `el done` кладёт задачу, ничего не подхватывается по свежести. Idle — полноправное состояние: `el`, `el status`, `el next`, `el where`, `el projects`, `ctx --line` говорят «в руке ничего» и показывают открытые + `el use <id>`; команды, которым нужна задача, отказывают с этой подсказкой (state.pick_task / no_task) вместо «no tasks». Попутно: `--task <несуществующий>` больше не падает молча на задачу в руке — «no task X» и rc 1 (было известной странностью). `touch` остался только для порядка в `el projects` («последним трогали»). Развилка «вычисляемое или хранимое» закрыта в пользу вычисляемого: журнал — единственная записанная правда. Рассмотрено и отклонено: хранить «в руке» в маркере `.elephant` (вторая правда) · legacy-откат на свежайший журнал для старых хранилищ (скрытая сложность; старое хранилище после обновления честно говорит idle, первый `el boot`/`el use` берёт задачу). Старые хранилища: один `el use` после обновления.

- **Форма `el blueprint` — один контур** *(решено владельцем 2026-08-22 после восьми отклонённых вариантов: «декларация этапа, этап, потом список… название такта, файл, под файлом required или optional, и с отступом — описание»)*. Каждая фаза печатается из одной таблицы тактов (`protocol.phase_beats`: контекст и думание — из своих лестниц, остальные — из `PHASE_BEATS` в форме `(название, от кого, след, порог, описание, команда)`, этап 0 — `STAGE0_BEATS`): строка-декларация `N/8 ФАЗА — название` → под ней мышление фазы · гейт · выход → такты с отступом → под каждым тактом карточка ещё глубже: `файл` (или `след`, если это не путь) · `required`/`optional` с порогом («всегда» / «с режима soft» / «обязателен с режима strict») и «от кого» · `описание` · `команда`. Режимы — в шапке как ползунок с маркером текущего; правила поверх фаз — тем же контуром. Перенос строк — по ширине терминала в момент печати (`shutil.get_terminal_size`, 64…110; в файл/пайп — 100) с висячим отступом, чтобы продолжение не прыгало в нулевую колонку; реального reflow при смене размера окна у терминала нет — только короткие строки. Отклонённое: таблицы с командой под строкой · однострочные таблицы · карточки · символы ●◐○ · лестница+таблица · группировка required-first · матрица режимов · минимальный список — все «хаотично, некрасиво»; английские абзацы `how` из blueprint убраны.
- **Режимы light · soft · strict и карта тактов в blueprint** *(решено владельцем 2026-08-22: «ползунок от мало required до ни одного optional»)*. У каждого такта всех фаз — порог (`CONTEXT_MIN`, `THINK_MIN`, третий элемент в `PHASE_MAP.artifacts`, `PHASE_BEATS` для не-файловых тактов plan/execute/validate/reflect/align/close); `required_in(порог, режим)`; `el blueprint` печатает все такты каждой фазы по порядку с меткой «[обязательно · всегда / с режима soft / только strict]» и предпросмотром `--mode`; `el mode [light|soft|strict] [--why]` — событие журнала, `el boot/new --mode`; `el status`/`el next` показывают режим, страница — бейдж. Light: контекст = вопросы · задача после уточнений · слово (рамка, research, области — по нужде); думание всё по нужде (правило «развилки закрыты» держится, если развилки есть); план = узлы с контрактом «результат + критерии» и слово; исполнение = граф узлов; проверка = вердикты и слово final. Strict: всё обязательно + этап раскладывается до старта + не меньше пяти критериев у узла + `--waive` не принимается. Вне режимов: слово человека, граф, вердикты. Старое `CONTEXT_OPTIONAL` = порог strict (поведение soft не изменилось).

Свежесть слова приёмки — решено владельцем («да, согласен требовать»): из validate `el forward` не пускает без `el accept`, записанного на этой фазе (по журналу: событие `accepted` с фазой validate позже входа в неё; вернулись назад и пришли снова — слово нужно заново); слово над планом не считается, `--waive` не обходит — третья большая остановка держится так же, как первые две.
