# Проверить гипотезу о el на полигоне — цикл саморазвития

summary: гипотеза → протокол с прогнозом до данных → варианты, отличающиеся одним → свежие агенты без памяти → слепая оценка → решение по заранее названному порогу → запись

Слово владельца 2026-10-11: «скажу „работай и улучшай" — формируй гипотезы, сам готовь полигон, сам проверяй и сверяй». Агент без памяти этого цикла не знает — он здесь.

## Цикл
1. **Гипотеза из данных, не из фантазии.** Источник — отчёт полигона (стены, молчание, приёмка), отзывы агентов, аудит. Одна фраза: «если el делает X, агенты делают Y лучше по мерке Z». Запиши в реестр гипотез дела полигона (`reports/hypotheses.md`): номер, фраза, откуда взялась, статус.
2. **Протокол до данных** (`reports/<имя>-prereg.md`) — доказательство своего пункта (`el todo done N.M file:reports/<имя>-prereg.md`): тогда el держит его версию и не просит править, а «записан до данных» стоит на неизменном файле. В нём: варианты; что одинаково во всех (модель, поручения, время); мерки и как считаются; прогноз числами; **порог отказа** — при каком исходе гипотезу отвергаем. Записан до первого прогона, не правится после.
3. **Варианты отличаются одним.** Прежний el (HEAD) против прототипа: `polygon.py prepare … --el-dir <папка с копией el>` — прототип живёт вне репозитория; правило агентам сообщает только el, поручения у всех вариантов одни и те же, об опыте агент не знает.
4. **Известная истина.** Материал, у которого правда уже установлена (документ с аудитом, заверенный контроль — и плохой, и хороший: без хорошего не видно, что проверка возвращает всё подряд).
5. **Руки разделены по-настоящему.** Если мерка про приёмку — исполнитель и проверяющий в разных сессиях (`one_session` по очереди), иначе один агент сыграет обе роли.
6. **Прогоны.** Минимум 2 на вариант; Codex дешевле для лимитов Claude, Haiku — строже к выводу el. Не больше 5 агентов разом.
7. **Слепая оценка.** Итоги перемешаны под случайными метками, ключ у ведущего; оценщик — отдельная сессия (Codex) тем же методом, что эталон.
8. **Решение по порогу из протокола.** Принять → партия el (код, тест, справка) и запись в реестре; отвергнуть → прототип в архив, вывод в реестр. Без подгонки: если исход не тот — так и записать.
9. **Отчёт** (`reports/<имя>.md`): вопрос, постановка, таблица, что значит, границы (n, кто оценивал), где прогоны.

## Пример цикла
H1 «приёмка партии по выборке» (2026-10-11): протокол с порогами до данных → четыре прогона с разделёнными руками → слепой
аудит 24 итогов под метками → оба порога отказа сработали → гипотеза отвергнута, el не менялся. Ход выглядел прорывным по
двум агентам прошлого опыта; честная постановка его не подтвердила — ради этого цикл и нужен.

## Ловушки
- Вывод из двух агентов одного опыта — гипотеза, не закон: следующие придут без памяти о нём; решающий опыт ставь с
  разделёнными ролями и слепой оценкой.
- Ключ слепой оценки — вне папки оценщиков (и проверь в их журналах, что к нему не обращались).
- Агенты выполняют написанное перед глазами дословно — поручение не должно подсказывать ответ.
- Журнал вызовов обёртки Codex считает записью вне границы и обходит — считай вызовы по записи сессии.
- `claude -p` на лимитах подписки: рой субагентов съедает лимит за полчаса — Sonnet с субагентами дорог.
- zsh не делит `$S` на слова — в скриптах стенда массивы `S=(…)` или bash.
- Время в протоколе — с часов (`date`), не на глаз; порядок «протокол до данных» доказывает время создания файла (`stat -f %SB`, равное времени изменения) против `meta/run.json` и первого журнала сессии — вписанное от руки время в обоих направлениях путало вторую руку.
- Поток `codex exec --json` несёт только главную нить: запуск субагента Codex в нём не виден (только `wait`), а прогоны полигона идут с `--ephemeral` — журналов нитей нет. Кто выдал вердикт, считай исключением по журналу обёртки el (`el-polygon/tools/hidden_calls.py`): вызов, которого нет ни в одной команде и ни в одном скрипте главной нити, сделал другой процесс. Отсутствие следа в одном потоке — не отсутствие действия.
- В живом деле номер пункта сквозной на всё дело (`3.85`, не `3.1`): скрипт раскладки берёт номер из ответа el (`added: N.M`), а «уже есть» ищет под своим пунктом — одноимённый подпункт соседней темы не тот.
- Опыт в живом деле, где рядом лежит прежняя версия того же документа: поручение запрещает её открывать и след сессии это проверяет — иначе новая версия не независима от старой.
- Мерка «потери и выдумки против эталона по итогу вместе с записями» пропускает дословную копию источника: запрет пересказа исполнитель доводит до зеркала, и оно проходит мерку почти без потерь. Мерь и то, что знает читатель одного итога, не открывая записей.
