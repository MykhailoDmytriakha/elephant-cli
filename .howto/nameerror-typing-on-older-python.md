# NameError на имя из typing при импорте — только на другой машине

**Что это.** Python 3.14 вычисляет аннотации типов лениво (PEP 649): `def f(x: Dict[str, int])` не трогает `Dict`, пока кто-то не спросит подсказки типов. Python ≤ 3.13 вычисляет аннотацию в момент `def` — модуль с именем, которого нет в `from typing import …`, не импортируется вообще. Поэтому на машине разработки (3.14) тесты зелёные, а на машине с 3.12/3.13 любой `el …` падает трейсбеком до разбора аргументов.

**Как чинить.** Добавить имя в `from typing import …` того модуля, на который указывает трейсбек. Проверить все модули сразу, не по одному:

```
python3 -m unittest tests.test_imports
```

Тест `tests/test_imports.py` вызывает `typing.get_type_hints` для каждой функции и класса пакета — это принудительное вычисление аннотаций на любой версии Python.

**Почему так.** Сборка ловится тем, что запускается там, где ей плохо. Пока нет второго интерпретатора под рукой, вычисление аннотаций в тесте — замена машины с 3.13. Случай 2026-09-09: `Dict` и `Tuple` в `commands.py` (F19 `_blocking`, три релиза незамеченными).
