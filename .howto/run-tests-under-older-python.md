# Отказ, которого у нас нет, — сначала прогон под старым Python

**Что это.** `bin/el` запускает `python3`, первый в `PATH` того, кто зовёт. У нас это 3.14 из Homebrew, а у Codex на той же машине — системный `/usr/bin/python3` 3.9. Тот же код ведёт себя по-разному. argparse до 3.13 отдаёт необязательный позиционный аргумент (`nargs="?"`, `"*"`) пустым на первом отрезке позиционных, и слова после опции возвращаются как «unrecognized arguments». Так `el todo note 1.1 --edit 1 "текст"` — форма из `el help todo` — отказывала у Codex и проходила у нас (три отзыва 2026-10-15…17; под 3.9 падали 21 тест из 1127). Аннотации типов — другой класс той же болезни: `nameerror-typing-on-older-python.md`.

**Как проверять.** Отзыв, который не воспроизводится у нас, гоняем под старым интерпретатором до любой правки:

```
/usr/bin/python3 elephant.py <команда из отзыва>
/usr/bin/python3 -m unittest discover -s tests -t . </dev/null
```

Весь набор под `/usr/bin/python3` — шаг каждой партии рядом с обычным прогоном.

**Как чинить.** Не через ветку под версию, а так, чтобы обе версии читали вызов одинаково. Для argparse это `_late_positionals` в `main.py`: слова, оставшиеся после разбора, отдаются пустому необязательному позиционному — как делает новый argparse. Тест эмулирует старый разбор в процессе (`tests/test_old_python_and_links_1020.py`), поэтому падает на старом коде под любым Python. Рядом стоит тест под настоящим `/usr/bin/python3`, пропускается там, где его нет.
