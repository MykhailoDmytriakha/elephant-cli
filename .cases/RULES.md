# RULES — правила `.cases/`

Полный набор правил по классам: **L** Layout — раскладка и имена · **F** Format — форматы файлов · **S** Stamp — отпечаток и якорь · **P** Procedure — процедура · **Q** Question — на согласование. Порядок нижнего слоя (F14, F15, S5, P12) инструмент показывает на каждом входе, но не запрещает — эти файлы пишет агент напрямую. Протокол (L, F, S) утверждается и превращается в тесты `el` — на корректность и на излом; процедура (P) шлифуется отдельно; Q — свой круг. Термины и имена — English, описания — по-русски. Читай целиком на входе; `el` (когда появится) печатает нужный кусок в момент письма — этот файл остаётся источником.

## L — раскладка и имена (протокол · утверждено владельцем 2026-08-29)
- L1 `.cases/` в корне проекта — все дела. Рядом `.howto/` — общие рецепты (knowledge base, работает и без CLI) и `scripts/` — общие скрипты.
- L2 Дело — `.cases/YYYY-MM-DD-name-in-english/`: дата рождения + имя через дефис (буквы, цифры). `case new` создаёт новые имена в нижнем регистре; имя дают словами владельца на любом языке — кириллица транслитерируется в имя папки (`договор с подрядчиком` → `2026-09-14-dogovor-s-podryadchikom`), а человеческое имя остаётся заголовком README (2026-09-14); **обнаружение — регистронезависимо и без лимита слов**, существующие папки никогда не переименовываются; папка, похожая на дело, но отвергнутая, называется вслух с причиной.
- L3 В деле ровно три файла верхнего уровня: `README.md` («сейчас») · `TODO.md` (фазы) · `JOURNAL.md` (история).
- L4 Всё остальное — в папках дела по виду содержимого: `phases/` · `research/` · `scripts/` · `docs/` · `logs/` · `meetings/` · `jira/` · `data/`. Не по дате, не по фазе. Рецептов в деле нет — все в `.howto/` (L7).
- L5 Папка появляется с первым файлом; имя — английское слово в нижнем регистре, дефис между словами. Каждая папка — строка в README `Links`.
- L6 Файлы в папках — English; много файлов одного вида → дата в имени: `meetings/2026-09-01-kickoff.md`.
- L7 Рецепт — `.howto/<task-verb>.md` в корне проекта (`get-logs-from-instances.md`); папка `.howto/<name>/` — только когда рецепту нужны свои файлы. Способ, нужный одному делу, — не рецепт, а строки в файле фазы.
- L8 Отпечаток дела — строка `stamp:` последней строкой каждого из трёх файлов (S1); отдельных файлов отпечатка нет.
- L9 Вложенное дело — папка той же формы (L2, L3) внутри папки родителя; глубина не ограничена. Родитель знает о ребёнке одной строкой (F6, P11); ребёнок о родителе — строкой `parent: [<case>](../README.md) · фаза N` в `Links` (у ребёнка проектного дела — `../../README.md`). Указатель на дело — везде одна форма: ссылка на его README, которую открывает редактор (отзыв 2026-09-30: голое имя папки не кликалось); строка, которую el писал голым именем до 1.31.0, перерисовывается ссылкой при следующей записи.
- L10 Люди — `.cases/people/<name>.md`, карточка на человека, с которым имеют дело несколько дел: секретарь, стейкхолдер, служба (слово владельца 2026-09-16). Внутри `.cases/`, а не рядом с `.howto/`: карточка — персональные данные, она прячется вместе с делами под тем же правилом `.gitignore`. Не дело: `el` её не сканирует как дело и ничего в неё не пишет — агент пишет карточку сам, как рецепт. Форма — та же, что у любого файла дела: заголовок именем человека, `summary:` второй строкой (роль · что за ним · как связаться — доза перед звонком или письмом), тело свободное (как с ним работать, что за ним, чего не отвечает); история общения — в журналах дел, не в карточке. Имя файла латиницей в нижнем регистре, роль вместо имени, если имени нет (`court-secretary-3.md`). Дело ссылается на карточку как на любой файл (`[Менука](../people/menuka-perera.md)` из `note` или из `Links`); ссылка проверяется F16, карточка без `summary:` — строка Order и предупреждение `check`. С нуля агент узнаёт о карточках из образца пункта после `case new` (заметка со ссылкой на карточку) и момента PEOPLE в `el help practice`; структурный толчок — строка Order «та же строка Links есть в деле X» (детектор троек F15 по ручным строкам Links всех дел: одно описание в двух делах → одна карточка и ссылка из обоих); подсказки: при `case new`/`spawn`, когда карточки уже есть, — «свяжи те, с кем имеет дело это дело»; на входе — строка Links, повторяющая `summary:` карточки, → заменить ссылкой. Не подсказываем по словам «позвонить», «спросить» — это гадание по тексту. Позже, по живому употреблению: `el who <name>` и строка «встречается в делах», собранная из ссылок. Не делаем: секцию README под людей (форма README — контракт), базу контактов с полями (второй источник истины).

## F — форматы файлов (протокол · утверждено владельцем 2026-08-30)
- F0 У трёх файлов первая строка — `# <Title>`, последняя — `stamp: <hash>` (S1); между ними содержимое.
- F1 README — секции ровно в этом порядке: `Context` · `State` · `Decisions` · `Problems` · `Links`. Других секций нет: границы — строка `не входит:` в `Context`; люди и среда — строки в `Links`; риски — строки `risk ·` в `Problems`.
- F2 README: 200 строк / 8 KB — предупреждение, 300 строк / 12 KB — отказ записи; строка-указатель ≤ 150 знаков — строки `Links` и `State`, где владелец кликает и скользит глазами; `Decisions`, `Problems`, `Context` — текст, ограниченный только байтами README (2026-09-17: 19 строк Decisions предупреждали неделями, никто не реагировал — правило сужено до того, о чём оно). Предупреждение при записи — только о строках, внесённых этой записью (как отказ — только о внесённых ошибках); история — дело `check`, и он называет её один раз на правило со списком строк. Считается текст, который пишут агент и владелец; вложенные строки `Links`, которые `el` рисует из файлов (файлы, подпапки, `other:`), называются в сообщении, но не считаются — их в README не сократить, и указатель файлов не должен вытеснять пять строк владельца (2026-09-03). Пяти секций достаточно (F1): тема проекта — строка `State` (`- budget: …`) или файл с `summary:`.
- F3 README пишется для человека, который не был в сессии: простыми словами, без внутреннего жаргона; термины English, объяснение по-русски. Секции: `Context` — цель словами владельца и чем меряем успех, 3–5 строк · `State` — строка `progress:` — все фазы с метками `✓` сделана · `▶` идёт · без метки впереди (собирается из TODO) · последний результат · следующий шаг · чего ждём · `Decisions` — `дата · что · вместо чего · почему`, отвергнутое тоже · `Problems` — только открытые (временное решение — строка с `workaround: …` и `until: YYYY-MM-DD`: у костыля есть момент возврата, `el` считает его на входе, 2026-09-15) · `Links` — строки агента про внешний мир (рецепты из `.howto/`, Jira, серверы, документы, кого спросить, соседние дела) и строки папок `- docs/ — что здесь`; файлы под папкой `el` рисует сам из их строк `summary:` (F14) — их руками не пишут; вложенные папки рисуются под родителем уровнем глубже строкой с полным путём `- docs/notes/ — описание` (описание — твоё, необязательное); строка агента про файл, который `el` не рисует, остаётся как написана — из `Links` ничего не выбрасывается молча (2026-09-03); строка про не-markdown файл внутри папки дела — это его описание, `el` рисует по ней ссылку и не дублирует файл в `other:` (2026-09-11). Строки `State`, которые держит `el`: `progress:` (из TODO) · `last:` (свежий RESULT) · `as of:` (S5). Строку `closed:` пишут только `el done` и `el case cancel`: итог пишется целиком (слово владельца 2026-09-25; до этого укорачивался до предела указателя), `readme set closed` — отказ: дело закрывается через гейты, не строкой (2026-09-15). Срок дела — строка `- due: YYYY-MM-DD · что` (`el readme set due "…"`): `el` считает дни до него на входе (2026-09-03). Секции-списки правятся по строке: `el readme add <section> "…"` · `edit <section> k "…"` (на месте, порядок сохранён) · `drop <section> k`; `readme set` пишет только `State` и отказывает, если префикс — строка другой секции (2026-09-08). Строку `next: open phase 1`, которую el пишет в новом деле, `phase open` снимает сам — это слова el, и после открытия фазы они врут; следующий шаг, написанный агентом, el не трогает (L2, 2026-10-05). Что README рисует сам (холодный читатель 2026-10-08: свежая модель, только README законченного дела, пять вопросов владельца, восемь живых дел — «с чего началось» не нашли 11 из 16, «какие решения» 10 из 16): первая строка State — `opened:` (дата и цель, с которой дело открыто; цель переписана — та, что была); под строками Decisions агента — пять новейших решений журнала с датой под строкой «from the journal — history, not the case's rules», служебные записи el (приёмка, reopen, reflect, align, howto, объём, снятие, пауза) не решения работы; ссылка журнала приходит своим именем. Инструкций агенту в README нет — пробелы (summary, описание папки) называет Order. С этим: 1 из 16 и 0 из 16. Нарисованное в пределах не считается.
- F4 TODO — только фазы и их пункты, ≤ 200 строк (было 100 до 0.20: прогон по пяти средам × 17 шагов плюс 26 строк фаз — 113 строк структуры, не воды; при 100 агент снимал живые фазы, чтобы влезть, 2026-09-09). Фаза: `- [ ] N Name`; пункт: `  - [ ] N.M text`; отложенный пункт: `  - [~] N.M text — hold: причина` (держится в конце фазы; причина обязательна, как у `cancel` и `reopen`: чего ждёт — заявка в чужой очереди, согласование, ответ; `[ ]` на таком пункте читается «делай сейчас», а отложка без причины — «сломано»; отзыв 2026-09-30); за причиной может стоять команда проверки выхода — `  - [~] N.M text — hold: причина — check: <команда>` (`el todo hold N.M "…" --check '…'`, L4): следующий агент приходит без памяти и проверяет стену, а не гадает; el её не запускает, нитка называет; живёт и уходит вместе с отложкой; в деле с правилом «две руки» сделанный пункт рисуется `  - [/] N.M text` до приёмки и `[x]` после неё (F23). Лимит текста — по видимым знакам: ссылка `[имя](путь)` считается как `имя`, других исключений нет — пункт длиннее 100 переформулируется, не пересчитывается (слово владельца 2026-09-15: глагол вперёд, путь остаётся, вводные слова уходят; отказ подсказывает переформулировать, а не обрезать; подсказка режет по последней границе смысла — `—` `;` `:` `·` `,` — и отдаёт остаток готовой командой как `note:` пункта, слова агента не теряются; границы нет — только «переформулируй», отзыв 2026-09-22). Строки считаются те, что пишет агент — фазы, пункты, `why:`, `note:`, `waits:`; строки `result:` и доказательств под ними рисует `el` из `done`, они называются, но не считаются (F22). Номер пункта N.M — на всю жизнь пункта: `drop` и `move` номера не меняют (`move N.M N.K` ставит перед N.K, `move N.M last` — последним), новый пункт получает следующий свободный номер; порядок строк и номера — разные вещи, пачка команд по только что прочитанным номерам остаётся верной, пропуски в номерах — норма (2026-09-03). `move N.M K` (номер фазы) переносит пункт в конец фазы K под следующим свободным номером — единственный случай, когда номер меняется. Срок пункта — суффикс `— due: YYYY-MM-DD` (после текста, перед `— hold:`), в лимит текста не входит; инструмент считает такие даты на входе. Пункт, переставший быть нужным, — `todo cancel N.M "почему"`: уходит из TODO (список — что осталось сделать, P4), причина — в журнал `DECISION · снято …`; не `done` (это ложь «сделано») и не `drop` (это молчание). Запланированная фаза — `- [ ] N Name — намерение` без файла фазы (`el phase plan N "Name" --goal "…"`, 2026-09-03): пункты в неё кладутся заранее (`todo add N`), в журнал она не пишет, открывается `phase open N` (имя и goal — из плана) и только когда предыдущая закрыта (P8): planned ≠ open.

Старые строки с хвостом ` · <case>/` читаются как есть.
- F7 JOURNAL — свежая запись сверху. Запись: `- YYYY-MM-DD HH:MM · pN`; под ней с отступом в два пробела строки событий `TYPE · текст`, ≤ 200 знаков; тело события — отступ четыре пробела, ≤ 5 строк. Длинный текст инструмент режет на заголовок и тело сам; перевод строки автора — своя строка тела (заголовок — первая строка), а не пробел (2026-09-14). Мягкий порог 180 («близко к пределу») говорит один раз `el log` о строке, которую только что записали; парсер и `check` историю этим не упрекают (2026-09-17: 46 из 66 предупреждений `check` были старыми строками журнала).
- F8 JOURNAL — `TYPE` ∈ { `PHASE`, `DECISION`, `PROBLEM`, `RESULT` }. Фаза записи — `--phase N`; без него — фаза, чьи пункты `N.M` названы в тексте (одна), иначе фаза в полёте; ответ команды говорит, куда легло (отзыв 2026-09-22: RESULT о пунктах 2.x лёг под p1).
- F9 JOURNAL — у каждой фазы есть хотя бы один `RESULT` до её закрытия.
- F10 Рецепт — первая строка `when:`: ошибка дословно, симптом, ситуация, с которыми агент придёт искать. Индекс не ведётся — `grep '^when:'`.
- F11 Скрипты — English целиком: имена, комментарии, docstring, вывод.
- F12 Файл фазы `phases/N-name.md` живёт с открытия фазы — тяжёлый низ для её деталей. Шапка жёсткая: `# Phase N — Name` · `goal:` одной строкой (может обещать, что фаза оставит после себя, скобками `[file: …] [run: …] [owner]`, как `expect:` пункта; обещание раскладывается на пункты: критерий со словами покрыт пунктом, чей `expect:` несёт тот же слот, и доказан, когда этот пункт сделан с доказательством того вида — фаза доказывается своими пунктами (Prove2Me); голый вид (`[owner]`) доказан любым сделанным пунктом этого вида; пока фаза идёт, Order называет обещанное доказательство, к которому ни один пункт не ведёт; `phase close` отказывает над недоказанным обещанием — два выхода: доказать пункт или поправить строку `goal:`; Digest — «phase promise: k of n proved — [run: …] by N.M · not proved: …» (отзыв 2026-09-16: фаза закрыта на baseline — HTTP 200 и benefits — при цели «скидка применена», `check` 0: четыре критерия одного вида закрывались одним прогоном); ожидание живёт на каждом размере узла: Context у дела, `goal:` у фазы, `expect:` у пункта — 2026-09-16) · `result:` — пусто, пока фаза идёт, при закрытии — тот же текст, что в строке-итоге TODO. Два честных хода: повторный `done` с этим файлом и словами записывает новую версию — это новое утверждение, поэтому RESULT пишется, приёмка снимается, старый вердикт остаётся историей; или `reopen`. `mv`, `relink` и `order --adopt` переписывают документы сами — в этом деле и в делах над ним — и переносят версию; правку автора, сделанную до них, не отмывают. Фаза — `result:`, дело — итог. Снято — с причиной: `todo cancel`, `phase cancel N "почему"`, `case cancel "почему"` пишут `DECISION · снято …` и сворачивают узел в строку у родителя с пометкой «снято». Родитель закрывается, только когда каждый ребёнок сделан или снят; `phase close` при открытых пунктах отказывает и называет оба выхода. Обратное направление показывается, не принуждается: фаза, у которой каждый пункт кончился, — строка `Order` «закрыть или дописать недостающее» с тем, чего закрытию ещё не хватает (2026-09-14). Галочка снимается назад с причиной: `todo reopen N.M "почему"` — пункт снова открыт, в журнале `DECISION · N.M возвращён в работу — …`, старый `RESULT` остаётся историей. `done`/`reopen`/`cancel` берут диапазон `N.A-N.B` или список `N.A, N.B` в одной фазе — одна запись журнала называет каждый номер. Снятая в плане (не открывавшаяся) фаза возвращается в план тем же `phase plan N`: пункты возвращаются под старыми номерами, рождённый при снятии файл уходит; бежавшая фаза не возвращается — новый номер (2026-09-09). Слова `done` — для владельца, которого не было в сессии: что вышло по пункту, простыми словами, в ответ на его `why:`; хэш commit, имя функции, оператор — след, а след это доказательство (`ref:<hash>`, `file:<исходник>`), не слова; инструмент видит класс токена и предупреждает, не отказывает (отзыв 2026-09-16: «Commit a1b2c3d4e5 removed region == EU check and gutted update()» там, где владелец спросил «почему отключили»). Инструмент проверяет структуру; правду о людях проверяет владелец.

Отказ говорит «нельзя, вот как», Order — «не на месте, вот команда», предупреждение — «записано, но посмотри»; подсказка `hint:` говорит «хорошо, а вот как отлично». Правила: подсказка выводится из состояния дела (пункт без `why`, доказательство только словом владельца, запланированная фаза без единой заметки, PROBLEM без рецепта в `.howto/`), а не из счётчика дней — совет по расписанию агент перестаёт читать за три входа (напоминание × плохая запись); одна на вывод, последней строкой, в stdout; рецитация — две строки `recite` каждые 10 вызовов el сессии на ближайшей команде над делом: нитка и что не отмечено с последнего `done` (слово владельца 2026-10-07: «команда каждые 10 вызовов»; поле — Manus, сходимость 6 обзора; `EL_RECITE=0` выключает) (на входе — сразу под Order, над телом дела: полигон 2026-10-07 — свежие агенты читали вход `el | head -60` и последней строки не видели; слово владельца «переворачивай»); называет одну команду с настоящим номером и тему `el help <topic>`; исчезает, когда сделано; никогда не о нарушениях — это Order и отказ. На входе из применимых выбирается одна по числу записей журнала: каждая запись сдвигает выбор, за сессию агент видит разные без файла состояния. `EL_HINTS=0` выключает. Тема `el help practice` — пары «слабо / сильно» по моментам (вход · пункт · done · проблема · парковка · костыль · закрытие фазы) и образец пункта; после `case new` образец печатается, чтобы было чему подражать. Каждая подсказка рождается из наблюдённого поведения агента; та, на которую не реагируют по замеру живого прогона (доля пунктов с `why`, доля доказательств не-`owner`, число рецептов), снимается. При `phase close` reflect или align, дословно повторяющие RESULT фазы (детектор троек F15, ≥ 50 %), называются предупреждением: результат, переодетый в урок.
- P15 Идущая фаза — не история (слово владельца 2026-09-17). «Правило живёт на двери записи, чтение не требует» защищает историю: закрытые фазы и старые дела читаются как есть, их не упрекают и не мигрируют руками. Но фаза, в которой работают сейчас, — это сама дверь записи, и она держится по текущей форме строго: `goal:` с обещанием (`[run: …] [file: …] [owner]`), `expect:` у каждого открытого пункта, вид у каждой галочки. Order называет, чего в идущей фазе не хватает; `check` считает галочку без вида в идущей фазе нарушением F20 (в закрытых — нет); с закрытых фаз ничего не спрашивается. Пришёл в старое дело — `migrate`, если оно до `el`, затем в порядок приводится только идущая фаза.
- P13 Дело в старом формате — файл без отпечатка `el` и вне грамматики: записи в него не идут, и пересборкой S4 он не чинится (она унесла бы содержимое в `.recover.md`). `el migrate` показывает план — что куда, что остаётся на ревью, ничего не меняет; `el migrate --apply` копирует файлы byte-for-byte в `legacy/<дата-время>/`, проверяет копию, пишет канонические файлы атомарно, при сбое возвращает архив. README — секции по имени (goal/context → Context, decisions, problems/risks → Problems, links), остальное в архиве и названо; TODO — заголовки → фазы, чекбоксы → пункты (длинные обрезаны, полный текст в архиве), фаза со всеми сделанными пунктами закрыта, её файл помечен `migrated from legacy` и гейты P8 её пропускают; JOURNAL не конвертируется — переносится руками через `el log`. `legacy/` не проверяется на summary. Только README не в грамматике — остальное пишется; только TODO — README пишется без синхронизации `progress:`. Дело до el в руках (журнал тронут последним) называется, а не выводится: вход печатает, что это, `el migrate` и открытые дела el с `el case use` — файлы остаются на диске как есть (живой проект 2026-09-25: сырые README и TODO — 27 KB). Папка без README, где el ничего не штамповал, — тоже дело до el: `el case list` считает её с legacy, `--all` называет; BROKEN — только дело, которое писал el и которое сломалось. Одно правило «что это за дело» для входа и для списка.
