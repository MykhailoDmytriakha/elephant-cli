# RULES — правила `.cases/`

Полный набор правил по классам: **L** Layout — раскладка и имена · **F** Format — форматы файлов · **S** Stamp — отпечаток и якорь · **P** Procedure — процедура · **Q** Question — на согласование. Порядок нижнего слоя (F14, F15, S5, P12) инструмент показывает на каждом входе, но не запрещает — эти файлы пишет агент напрямую. Протокол (L, F, S) утверждается и превращается в тесты `el` — на корректность и на излом; процедура (P) шлифуется отдельно; Q — свой круг. Термины и имена — English, описания — по-русски. Читай целиком на входе; `el` (когда появится) печатает нужный кусок в момент письма — этот файл остаётся источником.

## L — раскладка и имена (протокол · утверждено владельцем 2026-08-29)
- L1 `.cases/` в корне проекта — все дела. Рядом `.howto/` — общие рецепты (knowledge base, работает и без CLI) и `scripts/` — общие скрипты.
- L2 Дело — `.cases/YYYY-MM-DD-name-in-english/`: дата рождения + имя через дефис (буквы, цифры). `case new` создаёт новые имена в нижнем регистре; имя дают словами владельца на любом языке — кириллица транслитерируется в имя папки (`договор с подрядчиком` → `2026-09-14-dogovor-s-podryadchikom`), а человеческое имя остаётся заголовком README (2026-09-14); **обнаружение — регистронезависимо и без лимита слов**, существующие папки никогда не переименовываются; папка, похожая на дело, но отвергнутая, называется вслух с причиной.
- L3 В деле ровно три файла верхнего уровня: `README.md` («сейчас») · `TODO.md` (фазы) · `JOURNAL.md` (история).
- L4 Всё остальное — в папках дела по виду содержимого: `phases/` · `research/` · `scripts/` · `docs/` · `logs/` · `meetings/` · `jira/` · `data/`. Не по дате, не по фазе. Рецептов в деле нет — все в `.howto/` (L7).
- L5 Папка появляется с первым файлом; имя — английское слово в нижнем регистре, дефис между словами. Каждая папка — строка в README `Links`.
- L6 Файлы в папках — English; много файлов одного вида → дата в имени: `meetings/2026-09-01-kickoff.md`.
- L7 Рецепт — `.howto/<task-verb>.md` в корне проекта (`get-logs-from-instances.md`); папка `.howto/<name>/` — только когда рецепту нужны свои файлы. Способ, нужный одному делу, — не рецепт, а строки в файле фазы.
- L8 Отпечаток дела — строка `stamp:` последней строкой каждого из трёх файлов (S1); отдельных файлов отпечатка нет.
- L9 Вложенное дело — папка той же формы (L2, L3) внутри папки родителя; глубина не ограничена. Родитель знает о ребёнке одной строкой (F6, P11); ребёнок о родителе — строкой `parent: <case> · фаза N` в `Links`.

## F — форматы файлов (протокол · утверждено владельцем 2026-08-30)
- F0 У трёх файлов первая строка — `# <Title>`, последняя — `stamp: <hash>` (S1); между ними содержимое.
- F1 README — секции ровно в этом порядке: `Context` · `State` · `Decisions` · `Problems` · `Links`. Других секций нет: границы — строка `не входит:` в `Context`; люди и среда — строки в `Links`; риски — строки `risk ·` в `Problems`.
- F2 README: 200 строк / 8 KB — предупреждение, 300 строк / 12 KB — отказ записи; строка-указатель ≤ 150 знаков. Считается текст, который пишут агент и владелец; вложенные строки `Links`, которые `el` рисует из файлов (файлы, подпапки, `other:`), называются в сообщении, но не считаются — их в README не сократить, и указатель файлов не должен вытеснять пять строк владельца (2026-09-03). Пяти секций достаточно (F1): тема проекта — строка `State` (`- budget: …`) или файл с `summary:`.
- F3 README пишется для человека, который не был в сессии: простыми словами, без внутреннего жаргона; термины English, объяснение по-русски. Секции: `Context` — цель словами владельца и чем меряем успех, 3–5 строк · `State` — строка `progress:` — все фазы с метками `✓` сделана · `▶` идёт · без метки впереди (собирается из TODO) · последний результат · следующий шаг · чего ждём · `Decisions` — `дата · что · вместо чего · почему`, отвергнутое тоже · `Problems` — только открытые · `Links` — строки агента про внешний мир (рецепты из `.howto/`, Jira, серверы, документы, кого спросить, соседние дела) и строки папок `- docs/ — что здесь`; файлы под папкой `el` рисует сам из их строк `summary:` (F14) — их руками не пишут; вложенные папки рисуются под родителем уровнем глубже строкой с полным путём `- docs/notes/ — описание` (описание — твоё, необязательное); строка агента про файл, который `el` не рисует, остаётся как написана — из `Links` ничего не выбрасывается молча (2026-09-03); строка про не-markdown файл внутри папки дела — это его описание, `el` рисует по ней ссылку и не дублирует файл в `other:` (2026-09-11). Строки `State`, которые держит `el`: `progress:` (из TODO) · `last:` (свежий RESULT) · `as of:` (S5). Срок дела — строка `- due: YYYY-MM-DD · что` (`el readme set due "…"`): `el` считает дни до него на входе (2026-09-03). Секции-списки правятся по строке: `el readme add <section> "…"` · `edit <section> k "…"` (на месте, порядок сохранён) · `drop <section> k`; `readme set` пишет только `State` и отказывает, если префикс — строка другой секции (2026-09-08).
- F4 TODO — только фазы и их пункты, ≤ 200 строк (было 100 до 0.20: прогон по пяти средам × 17 шагов плюс 26 строк фаз — 113 строк структуры, не воды; при 100 агент снимал живые фазы, чтобы влезть, 2026-09-09). Фаза: `- [ ] N Name`; пункт: `  - [ ] N.M text`; отложенный пункт: `  - [~] N.M text — hold: причина` (держится в конце фазы). Лимит текста — по видимым знакам: ссылка `[имя](путь)` считается как `имя`. Номер пункта N.M — на всю жизнь пункта: `drop` и `move` номера не меняют (`move N.M N.K` ставит перед N.K, `move N.M last` — последним), новый пункт получает следующий свободный номер; порядок строк и номера — разные вещи, пачка команд по только что прочитанным номерам остаётся верной, пропуски в номерах — норма (2026-09-03). `move N.M K` (номер фазы) переносит пункт в конец фазы K под следующим свободным номером — единственный случай, когда номер меняется. Срок пункта — суффикс `— due: YYYY-MM-DD` (после текста, перед `— hold:`), в лимит текста не входит; инструмент считает такие даты на входе. Пункт, переставший быть нужным, — `todo cancel N.M "почему"`: уходит из TODO (список — что осталось сделать, P4), причина — в журнал `DECISION · снято …`; не `done` (это ложь «сделано») и не `drop` (это молчание). Запланированная фаза — `- [ ] N Name — намерение` без файла фазы (`el phase plan N "Name" --goal "…"`, 2026-09-03): пункты в неё кладутся заранее (`todo add N`), в журнал она не пишет, открывается `phase open N` (имя и goal — из плана) и только когда предыдущая закрыта (P8): planned ≠ open.
- F5 TODO — закрытая фаза одной строкой: `- [x] N Name — результат · дата · проблемы → решения · замер · [phases/N-name.md](phases/N-name.md)`. Путь к файлу фазы — всегда markdown-ссылка (голый путь для редактора — текст, не ссылка); пункты, которые `phase close`/`cancel` переносит в файл фазы, сохраняют свои ссылки — пути перебазируются (`docs/x.md` → `../docs/x.md`). TODO держит «что» — фазы, пункты N.M, галочки; «как и почему» — в файле фазы (F12).
- F6 TODO — ожидание вложенного дела: строка `waits: <case>` в фазе; закрылось → `- [x] N.M <итог ребёнка> · <case>/`.
- F7 JOURNAL — свежая запись сверху. Запись: `- YYYY-MM-DD HH:MM · pN`; под ней с отступом в два пробела строки событий `TYPE · текст`, ≤ 200 знаков; тело события — отступ четыре пробела, ≤ 5 строк.
- F8 JOURNAL — `TYPE` ∈ { `PHASE`, `DECISION`, `PROBLEM`, `RESULT` }.
- F9 JOURNAL — у каждой фазы есть хотя бы один `RESULT` до её закрытия.
- F10 Рецепт — первая строка `when:`: ошибка дословно, симптом, ситуация, с которыми агент придёт искать. Индекс не ведётся — `grep '^when:'`.
- F11 Скрипты — English целиком: имена, комментарии, docstring, вывод.
- F12 Файл фазы `phases/N-name.md` живёт с открытия фазы — тяжёлый низ для её деталей. Шапка жёсткая: `# Phase N — Name` · `goal:` одной строкой · `result:` — пусто, пока фаза идёт, при закрытии — тот же текст, что в строке-итоге TODO. Тело свободное: разбор пунктов N.M, находки, тупики, замеры, черновики. Второго списка галочек в нём нет — это дубль TODO.
- F13 Имена в TODO. Фаза — English, 1–3 слова, существительное-результат (`Research`, `Concept`, `CLI core`), не занятие; имя фазы = имя файла `phases/N-name.md`. Пункт N.M — одно действие с проверяемым исходом: глагол в начале, ≤ 100 видимых знаков (было 80 до 0.21: шаг прогона `<Env>: [<Block>] <Action> -> expect <Result>` — это одно действие вместе с проверяемым исходом, и 80 сжимали его до `ENABLED=1`; 100 с префиксом `  - [ ] NN.MM ` ещё влезает в строку терминала, 2026-09-09), без «и» между двумя делами. Глубже N.M не дробим — третий уровень в файле фазы. Строка-итог закрытой фазы начинается с результата, не с процесса.
- F14 Файл в папке дела (`docs/`, `research/`, … — все, кроме `phases/` и `scripts/`) в первых пяти строках несёт `summary: <одна фраза ≤ 120 знаков>` — файл описывает себя сам; из этих строк собирается `Links`. Файл фазы описывает себя строкой `goal:`, закрытый — `result:`; рецепт — `when:`. Нет строки — `Order` называет файл; описание, написанное в `Links`, переносится в файл командой `el order --adopt`. Файл не-markdown (pdf, html, png, скрипт) тела не имеет — его описание живёт строкой в `Links` (`el readme add links "docs/council/send.html — что это"`): с описанием он рисуется ссылкой среди документов папки, без описания остаётся в свёрнутой строке `other:` (2026-09-11). Суффикс решает, откуда берётся описание, а не есть ли у файла право на строку.
- F15 Бюджет нижнего слоя: файл > 24 KB — «раздели по summary или сократи»; два файла, у которых ≥ 50 % фраз меньшего (тройки слов подряд) дословно есть в другом, — «назови разницу в summary или слей». Показывается, не запрещается: предел только на README сдвигал воду этажом ниже (замер на живом деле 2026-09-01: папка 79 KB за два дня). Бюджета папки нет (снят 2026-09-03): те 79 KB оказались рабочими документами — счётчик байтов не отличает deliverables от воды, а строка, которую можно закрыть только удалением хорошей работы, учит не читать `Order`. Дубликат — по дословным фразам, не по словарю: два документа об одном предмете делят имена и даты (46 % общих слов при 34 % общих фраз), копия — 80 %+.
- F16 Ссылка `[имя](путь)` ведёт на существующий файл. В README и TODO мёртвая ссылка — нарушение `check` (владелец кликает — ничего не открывается, а читает он строку `violations:`); в документах, файлах фаз и журнале — строка `Order` (в журнале считаются только цели, похожие на файл: `docs/x.md`, не `path` — история вправе привести пример, но не тупик). Файлы переносятся `el mv old new` — ссылки едут за файлом (2026-09-03); перенесён мимо `el` — `el relink old new` переписывает ссылки, журнал включительно; удалён насовсем или ссылка была примером — `el relink old none` превращает такие ссылки в текст в обратных кавычках: слова остаются, претензия на файл уходит (2026-09-08).
- F17 Правило дела «пункт ведёт к материалу» — строка `Context` `- rule: items link their material` (`el readme add context "…"`): пока она есть, `todo add`/`edit` предупреждают о пункте без ссылки `[имя](путь)`, а `Order` называет открытые пункты без неё. Включается там, где владелец читает только README и TODO, а работа живёт в документах; в деле про код не включается (2026-09-04). Строки `State`, которые держит `el` (`progress:` на много фаз), из предела F2 на указатель исключены — их агенту не сократить.
- F18 Закон свёрнутого узла (2026-09-05, концепция `research/work-graph.md`, слом Codex). Строка узла у родителя рисуется из шапки самого узла и руками не пишется: файл — из `summary:` (F14); закрытая фаза — из `result:` (F5); открытая фаза — из `goal:` плюс путь к файлу фазы (нажал — попал в развёрнутую); вложенное дело — из `progress:` · `next:` · `closed:` ребёнка в блоке Links родителя: открытые — строкой каждое, закрытые — числом и последними пятью, полное дерево — `el case list`; нечитаемый ребёнок — строка BROKEN, и он держит родителя открытым; ребёнок при закрытии пишет родителю всегда, как бы ни был создан.
- F19 Зависимости. Суффикс пункта `— after: N.M[, N.K, имя-дела]` (перед `due` и `hold`); цель обязана существовать; циклов нет по всем рёбрам вместе (`after`, `waits`, вложенность); номер, на который ссылаются (в `after` или в журнале), не переиспользуется; при переносе пункта ссылки переписываются за ним; drop пункта, на который ссылаются, — отказ; снятый пункт зависимость не закрывает — зависимый показывается «blocked by cancelled» с двумя выходами (перевязать `todo after`, снять). На входе строка `unblocked:` — открытые пункты без открытых блокеров, по сроку и фазе; в README она не пишется, `next:` остаётся словом владельца.
- F20 Два конца у узла любого размера. Сделано — со свидетельством: `todo done N.M "что вышло"` пишет `RESULT · N.M: …` (ссылка на артефакт — норма), фаза — `result:`, дело — итог. Снято — с причиной: `todo cancel`, `phase cancel N "почему"`, `case cancel "почему"` пишут `DECISION · снято …` и сворачивают узел в строку у родителя с пометкой «снято». Родитель закрывается, только когда каждый ребёнок сделан или снят; `phase close` при открытых пунктах отказывает и называет оба выхода. Галочка снимается назад с причиной: `todo reopen N.M "почему"` — пункт снова открыт, в журнале `DECISION · N.M возвращён в работу — …`, старый `RESULT` остаётся историей. `done`/`reopen`/`cancel` берут диапазон `N.A-N.B` или список `N.A, N.B` в одной фазе — одна запись журнала называет каждый номер. Снятая в плане (не открывавшаяся) фаза возвращается в план тем же `phase plan N`: пункты возвращаются под старыми номерами, рождённый при снятии файл уходит; бежавшая фаза не возвращается — новый номер (2026-09-09). Инструмент проверяет структуру; правду о людях проверяет владелец.
- F21 Unreferenced. Корни — рукописные строки README, тексты пунктов TODO, файлы фаз и события `RESULT`/`DECISION` журнала; живое — достижимое от корней по ссылкам `[имя](путь)` и по голым путям к `.md` (`research/survey.md`, в том числе в обратных кавычках — так цитируют файлы агенты и строки закрытых фаз), транзитивно через документы; автоуказатель Links ссылкой не считается, пример в блоке кода — тоже. Файл вне достижимости — строка Order «nothing in the work points at …», только показ: сослаться из работы, унести в `archive/` (`el mv`) или удалить руками. `archive/` и `legacy/` вне проверки. Введено последним и калибруется на живом деле. Отложено на следующий круг: свидетельство с отпечатком (хеши использованных файлов в RESULT → «сделано против изменившегося»), покрытие требований Context пунктами, `reconcile`.

## S — отпечаток (протокол · утверждено владельцем 2026-08-30)
- S1 Отпечаток — **последняя** строка каждого из трёх файлов, перед ней одна пустая строка: `stamp: <sha256, первые 12 знаков>` от содержимого выше (пустая строка в хэш не входит). Не последняя (что-то дописано после) — считается несовпадением. Ни копий, ни папки `.stamp/`; папки дела не хэшируются.
- S2 Ставит только `el`, после каждой своей записи. Строки нет — `el` ставит её на текущее содержимое.
- S3 Сверяется только при записи через `el`. Ни таймера, ни pre-commit: три файла трогают регулярно; не трогают — дело на паузе, ждёт или закрыто.
- S4 Не сошёлся → `el` пересобирает файл по грамматике F: разбираемое остаётся, неразбираемое — в `<FILE>.recover.md`; агент вносит его командами и удаляет; в лог — WARN «запись мимо el». Данные не теряются, файл всегда валиден.
- S5 Якорь «сейчас»: строка `- as of: <дата время · pN>` в `State` — заголовок самой свежей записи журнала на момент, когда агент переписал `State` (`el readme`, `readme set`, `done`). Событие `RESULT` или `PHASE` после якоря = «сейчас» отстало от истории; `el` называет это на входе и в `check`, пока `State` не переписан. Истинность инструмент проверить не может — свежесть может. `State` прочитан и по-прежнему верен — `el readme touch` переставляет якорь, не меняя текста (2026-09-08).

## P — процедура (утверждено владельцем 2026-08-30, P11 — 00:16 · шлифуется по логу)
- P1 Вход: `RULES.md` → README дела → TODO → 10 последних записей JOURNAL. Больше на входе не читай.
- P2 Одно дело в руке; один агент на одно дело в одно время; всё пишется в папку дела.
- P3 Три файла (README.md, TODO.md, JOURNAL.md) пишутся через `el`; читаются напрямую.
- P4 README — всегда текущее состояние: устаревшее убирается, не копится; подробности — в файл, в README строка-указатель.
- P5 JOURNAL — только дописывай, новая запись всегда сверху. Запись = событие, меняющее знание следующего читателя; действие (прочитал, запустил, поправил строку, переставил пункт TODO) — не событие, и сам `el` таких строк не пишет (с 0.9; в 0.7–0.8 писал — вход их прячет). `RESULT` пишется по-человечески: что сделали и что получилось; всё сделанное получает `RESULT`.
- P6 Упёрся → сначала поиск: `.howto/` по строке `when:` и тексту ошибки, затем `PROBLEM` по журналам. Решай только то, чего там нет.
- P7 Решил проблему → сразу `PROBLEM` в журнал и рецепт в `.howto/`, и в рецепте сразу первая строка `when:` (F10). Не жди повторения.
- P8 Открыл фазу → создан `phases/N-name.md` с шапкой (F12). Закрыл фазу или дело → `result:` в файле фазы заполнен, фаза свёрнута в TODO (F5), `PHASE` с `RESULT` в журнале, README `State` обновлён — и обязательно **reflect** и **align**: под датой закрытия в журнале `DECISION · reflect: <что в процессе поправить, урок>` и `DECISION · align: <план следующей фазы уточнён тем, что теперь знаем>`; пункты следующей фазы в TODO переписаны. Без reflect и align следующая фаза не открывается; снятая фаза (`phase cancel`) не бежала — с неё ничего не спрашивается. Назвать её заранее можно (`phase plan`, F4) — в работе всё равно одна, и фазы идут по порядку: запланированная ниже сначала открывается или снимается. Запланированную и не открытую фазу нельзя закрыть, даже если её пункты сделаны в TODO: сначала `phase open N` (гейты предыдущей и событие `PHASE`), потом `close` (2026-09-09).
- P9 Скрипт рождается в `scripts/` дела; в `scripts/` корня переезжает, когда понадобился второму делу. Рецепт сразу в `.howto/`.
- P10 Что куда:
  - прочитал, запустил, поправил → никуда, это git
  - факт, нужный, чтобы продолжить дело → README `State` или `Decisions`
  - решил проблему → JOURNAL `PROBLEM` · рецепт `.howto/<task-verb>.md` с `when:` · строка в README `Links`
  - способ делать частую операцию → `.howto/<task-verb>.md` с `when:`; скрипт → `scripts/` дела
  - скрипт пригодился второму делу → `scripts/` корня
  - получил файл, документ, лог, запись встречи → папка дела по виду · `summary:` второй строкой файла · строка папки в `Links` (файлы под ней `el` допишет сам)
  - два файла с общим текстом (`Order` назвал) → назвать разницу в `summary:` обоих или слить в один
  - заканчиваю сессию → `el`: `Order` говорит «State is behind» → переписать `State` (`el readme set next …`) или, если он верен как есть, подтвердить (`el readme touch`)
  - закрыл фазу → TODO строка-итог · JOURNAL `PHASE` + `RESULT` + `reflect:` + `align:` · README `State` · пункты следующей фазы переписаны
  - снял замер → JOURNAL `RESULT` · число в `State`
  - у куска работы есть дата → `— due: YYYY-MM-DD` в тексте пункта; срок дела → `el readme set due "YYYY-MM-DD · что"`
  - пункт больше не нужен → `el todo cancel N.M "почему"` — не `done`, не `drop`
  - переименовал или перенёс файл → `el mv old new` — ссылки в README/TODO/JOURNAL и в документах переписаны; перенёс мимо `el` → `el relink old new`; битые ссылки называет `Order`
  - в тексте есть `$` (суммы) → одинарные кавычки: в двойных shell съедает `$150`, а след (двойной пробел, сирота `.72`) `el` отказывает записывать
  - причина неизвестна или дело слишком большое → вложенное дело (P11)
- P11 Дело внутри дела. Знаешь, что делать, — пункт N.M; не знаешь почему, или это больше одной сессии, или нужно решение владельца — вложенное дело. Сложное дело делится на вложенные дела по частям. `el spawn <name>`: создаёт ребёнка (L9), в родителе — `waits:` в фазе (F6), «ждёт: …» в `State`, `PROBLEM … open → <case>` в журнале; рука переходит ребёнку, родитель стоит. `el done` в ребёнке: `result:` заполнен, README ребёнка сжат до итога; в родителя одной строкой — журнал (`PROBLEM` закрыт или `RESULT` · `<case>/`), TODO (`[x] N.M`), `State` («ждёт» снято); рука возвращается родителю. Пункт разросся → `el spawn` из пункта; дело закрылось за полчаса — нормально.
- P12 Порядок держит вход, не память агента: каждый `el` заканчивается блоком `## Order` — по строке на то, что не на месте (нет `summary:`, папка без описания, дубликат, файл над бюджетом, `State` отстал, файл не в папке, `.recover.md`, просроченный пункт, битая ссылка), и команда, которая это чинит. Пусто — «✓ everything in place». Первым сообщением сессии агент пересказывает своими словами, где дело стоит и что дальше (передача принята, не только записана).
- P13 Дело в старом формате — файл без отпечатка `el` и вне грамматики: записи в него не идут, и пересборкой S4 он не чинится (она унесла бы содержимое в `.recover.md`). `el migrate` показывает план — что куда, что остаётся на ревью, ничего не меняет; `el migrate --apply` копирует файлы byte-for-byte в `legacy/<дата-время>/`, проверяет копию, пишет канонические файлы атомарно, при сбое возвращает архив. README — секции по имени (goal/context → Context, decisions, problems/risks → Problems, links), остальное в архиве и названо; TODO — заголовки → фазы, чекбоксы → пункты (длинные обрезаны, полный текст в архиве), фаза со всеми сделанными пунктами закрыта, её файл помечен `migrated from legacy` и гейты P8 её пропускают; JOURNAL не конвертируется — переносится руками через `el log`. `legacy/` не проверяется на summary. Только README не в грамматике — остальное пишется; только TODO — README пишется без синхронизации `progress:`.
