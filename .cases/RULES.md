# RULES — правила `.cases/`

Полный набор правил по классам: **L** Layout — раскладка и имена · **F** Format — форматы файлов · **S** Stamp — отпечаток и якорь · **P** Procedure — процедура · **Q** Question — на согласование. Порядок нижнего слоя (F14, F15, S5, P12) инструмент показывает на каждом входе, но не запрещает — эти файлы пишет агент напрямую. Протокол (L, F, S) утверждается и превращается в тесты `el` — на корректность и на излом; процедура (P) шлифуется отдельно; Q — свой круг. Термины и имена — English, описания — по-русски. Читай целиком на входе; `el` (когда появится) печатает нужный кусок в момент письма — этот файл остаётся источником.

## L — раскладка и имена (протокол · утверждено владельцем 2026-08-29)
- L1 `.cases/` в корне проекта — все дела. Рядом `.howto/` — общие рецепты (knowledge base, работает и без CLI) и `scripts/` — общие скрипты.
- L2 Дело — `.cases/YYYY-MM-DD-name-in-english/`: дата рождения + имя через дефис (буквы, цифры). `case new` создаёт новые имена в нижнем регистре; имя дают словами владельца на любом языке — кириллица транслитерируется в имя папки (`договор с подрядчиком` → `2026-09-14-dogovor-s-podryadchikom`), а человеческое имя остаётся заголовком README (2026-09-14); **обнаружение — регистронезависимо и без лимита слов**, существующие папки никогда не переименовываются; папка, похожая на дело, но отвергнутая, называется вслух с причиной.
- L3 В деле ровно три файла верхнего уровня: `README.md` («сейчас») · `TODO.md` (фазы) · `JOURNAL.md` (история).
- L4 Всё остальное — в папках дела по виду содержимого: `phases/` · `research/` · `scripts/` · `docs/` · `logs/` · `meetings/` · `jira/` · `data/`. Не по дате, не по фазе. Рецептов в деле нет — все в `.howto/` (L7).
- L5 Папка появляется с первым файлом; имя — английское слово в нижнем регистре, дефис между словами. Каждая папка — строка в README `Links`.
- L6 Файлы в папках — English; много файлов одного вида → дата в имени: `meetings/2026-09-01-kickoff.md`.
- L7 Рецепт — `.howto/<task-verb>.md` в корне проекта (`get-logs-from-instances.md`); папка `.howto/<name>/` — только когда рецепту нужны свои файлы. Способ, нужный одному делу, — не рецепт, а строки в файле фазы.
- L8 Отпечаток дела — строка `stamp:` последней строкой каждого из трёх файлов (S1); отдельных файлов отпечатка нет.
- L9 Вложенное дело — папка той же формы (L2, L3) внутри папки родителя; глубина не ограничена. Родитель знает о ребёнке одной строкой (F6, P11); ребёнок о родителе — строкой `parent: <case> · фаза N` в `Links`.

## F — форматы файлов (протокол · утверждено владельцем 2026-08-30)
- F0 У трёх файлов первая строка — `# <Title>`, последняя — `stamp: <hash>` (S1); между ними содержимое.
- F1 README — секции ровно в этом порядке: `Context` · `State` · `Decisions` · `Problems` · `Links`. Других секций нет: границы — строка `не входит:` в `Context`; люди и среда — строки в `Links`; риски — строки `risk ·` в `Problems`.
- F2 README: 200 строк / 8 KB — предупреждение, 300 строк / 12 KB — отказ записи; строка-указатель ≤ 150 знаков. Считается текст, который пишут агент и владелец; вложенные строки `Links`, которые `el` рисует из файлов (файлы, подпапки, `other:`), называются в сообщении, но не считаются — их в README не сократить, и указатель файлов не должен вытеснять пять строк владельца (2026-09-03). Пяти секций достаточно (F1): тема проекта — строка `State` (`- budget: …`) или файл с `summary:`.
- F3 README пишется для человека, который не был в сессии: простыми словами, без внутреннего жаргона; термины English, объяснение по-русски. Секции: `Context` — цель словами владельца и чем меряем успех, 3–5 строк · `State` — строка `progress:` — все фазы с метками `✓` сделана · `▶` идёт · без метки впереди (собирается из TODO) · последний результат · следующий шаг · чего ждём · `Decisions` — `дата · что · вместо чего · почему`, отвергнутое тоже · `Problems` — только открытые (временное решение — строка с `workaround: …` и `until: YYYY-MM-DD`: у костыля есть момент возврата, `el` считает его на входе, 2026-09-15) · `Links` — строки агента про внешний мир (рецепты из `.howto/`, Jira, серверы, документы, кого спросить, соседние дела) и строки папок `- docs/ — что здесь`; файлы под папкой `el` рисует сам из их строк `summary:` (F14) — их руками не пишут; вложенные папки рисуются под родителем уровнем глубже строкой с полным путём `- docs/notes/ — описание` (описание — твоё, необязательное); строка агента про файл, который `el` не рисует, остаётся как написана — из `Links` ничего не выбрасывается молча (2026-09-03); строка про не-markdown файл внутри папки дела — это его описание, `el` рисует по ней ссылку и не дублирует файл в `other:` (2026-09-11). Строки `State`, которые держит `el`: `progress:` (из TODO) · `last:` (свежий RESULT) · `as of:` (S5). Строку `closed:` пишут только `el done` и `el case cancel`: итог укорачивается до предела указателя (полный текст — в журнале), `readme set closed` — отказ: дело закрывается через гейты, не строкой (2026-09-15). Срок дела — строка `- due: YYYY-MM-DD · что` (`el readme set due "…"`): `el` считает дни до него на входе (2026-09-03). Секции-списки правятся по строке: `el readme add <section> "…"` · `edit <section> k "…"` (на месте, порядок сохранён) · `drop <section> k`; `readme set` пишет только `State` и отказывает, если префикс — строка другой секции (2026-09-08).
- F4 TODO — только фазы и их пункты, ≤ 200 строк (было 100 до 0.20: прогон по пяти средам × 17 шагов плюс 26 строк фаз — 113 строк структуры, не воды; при 100 агент снимал живые фазы, чтобы влезть, 2026-09-09). Фаза: `- [ ] N Name`; пункт: `  - [ ] N.M text`; отложенный пункт: `  - [~] N.M text — hold: причина` (держится в конце фазы). Лимит текста — по видимым знакам: ссылка `[имя](путь)` считается как `имя`, других исключений нет — пункт длиннее 100 переформулируется, не пересчитывается (слово владельца 2026-09-15: глагол вперёд, путь остаётся, вводные слова уходят; отказ подсказывает переформулировать, а не обрезать). Строки считаются те, что пишет агент — фазы, пункты, `why:`, `note:`, `waits:`; строки `result:` и доказательств под ними рисует `el` из `done`, они называются, но не считаются (F22). Номер пункта N.M — на всю жизнь пункта: `drop` и `move` номера не меняют (`move N.M N.K` ставит перед N.K, `move N.M last` — последним), новый пункт получает следующий свободный номер; порядок строк и номера — разные вещи, пачка команд по только что прочитанным номерам остаётся верной, пропуски в номерах — норма (2026-09-03). `move N.M K` (номер фазы) переносит пункт в конец фазы K под следующим свободным номером — единственный случай, когда номер меняется. Срок пункта — суффикс `— due: YYYY-MM-DD` (после текста, перед `— hold:`), в лимит текста не входит; инструмент считает такие даты на входе. Пункт, переставший быть нужным, — `todo cancel N.M "почему"`: уходит из TODO (список — что осталось сделать, P4), причина — в журнал `DECISION · снято …`; не `done` (это ложь «сделано») и не `drop` (это молчание). Запланированная фаза — `- [ ] N Name — намерение` без файла фазы (`el phase plan N "Name" --goal "…"`, 2026-09-03): пункты в неё кладутся заранее (`todo add N`), в журнал она не пишет, открывается `phase open N` (имя и goal — из плана) и только когда предыдущая закрыта (P8): planned ≠ open.
- F5 TODO — закрытая фаза одной строкой: `- [x] N Name — результат · дата · проблемы → решения · замер · [phases/N-name.md](phases/N-name.md)`. Путь к файлу фазы — всегда markdown-ссылка (голый путь для редактора — текст, не ссылка); пункты, которые `phase close`/`cancel` переносит в файл фазы, едут со своими карманами (F22) и сохраняют свои ссылки — пути перебазируются (`docs/x.md` → `../docs/x.md`). TODO держит «что» — фазы, пункты N.M, галочки; «как и почему» — в файле фазы (F12).
- F6 TODO — ожидание вложенного дела: строка `waits: <case>` в фазе; закрылось → `- [x] N.M <итог ребёнка> · <case>/`.
- F7 JOURNAL — свежая запись сверху. Запись: `- YYYY-MM-DD HH:MM · pN`; под ней с отступом в два пробела строки событий `TYPE · текст`, ≤ 200 знаков; тело события — отступ четыре пробела, ≤ 5 строк. Длинный текст инструмент режет на заголовок и тело сам; перевод строки автора — своя строка тела (заголовок — первая строка), а не пробел (2026-09-14).
- F8 JOURNAL — `TYPE` ∈ { `PHASE`, `DECISION`, `PROBLEM`, `RESULT` }.
- F9 JOURNAL — у каждой фазы есть хотя бы один `RESULT` до её закрытия.
- F10 Рецепт — первая строка `when:`: ошибка дословно, симптом, ситуация, с которыми агент придёт искать. Индекс не ведётся — `grep '^when:'`.
- F11 Скрипты — English целиком: имена, комментарии, docstring, вывод.
- F12 Файл фазы `phases/N-name.md` живёт с открытия фазы — тяжёлый низ для её деталей. Шапка жёсткая: `# Phase N — Name` · `goal:` одной строкой · `result:` — пусто, пока фаза идёт, при закрытии — тот же текст, что в строке-итоге TODO. Тело свободное: разбор пунктов N.M, находки, тупики, замеры, черновики. Второго списка галочек в нём нет — это дубль TODO. Секции, которые рисует `el`: `## Before opening` при открытии — записи журнала, отложенные на эту фазу (`el log --phase N …`, пока она была запланирована); `## Digest` при закрытии — пункты (и сколько различных доказательств за ними стоит), заметки, RESULT уровня фазы (результаты пунктов лежат под пунктами ниже), PROBLEM, DECISION, reflect и align этой фазы из журнала (выжимка рисуется, не пишется: бедный журнал — бедная выжимка; 2026-09-16: выжимка повторяла четыре результата пунктов); `## Items at close` / `## Items at cancel` — пункты с карманами; `## Notes at cancel` — заметки снятой фазы (2026-09-15).
- F13 Имена в TODO. Фаза — English, 1–3 слова, существительное-результат (`Research`, `Concept`, `CLI core`), не занятие; имя фазы = имя файла `phases/N-name.md`. Пункт N.M — одно действие с проверяемым исходом: глагол в начале, ≤ 100 видимых знаков (было 80 до 0.21: шаг прогона `<Env>: [<Block>] <Action> -> expect <Result>` — это одно действие вместе с проверяемым исходом, и 80 сжимали его до `ENABLED=1`; 100 с префиксом `  - [ ] NN.MM ` ещё влезает в строку терминала, 2026-09-09), без «и» между двумя делами. Глубже N.M не дробим — третий уровень в файле фазы. Строка-итог закрытой фазы начинается с результата, не с процесса.
- F14 Файл в папке дела (`docs/`, `research/`, … — все, кроме `phases/` и `scripts/`) в первых пяти строках несёт `summary: <одна фраза ≤ 120 знаков>` — файл описывает себя сам; из этих строк собирается `Links`. Файл фазы описывает себя строкой `goal:`, закрытый — `result:`; рецепт — `when:`. Нет строки — `Order` называет файл; описание, написанное в `Links`, переносится в файл командой `el order --adopt`. Файл не-markdown (pdf, html, png, скрипт) тела не имеет — его описание живёт строкой в `Links` (`el readme add links "docs/council/send.html — что это"`): с описанием он рисуется ссылкой среди документов папки, без описания остаётся в свёрнутой строке `other:` (2026-09-11). Суффикс решает, откуда берётся описание, а не есть ли у файла право на строку.
- F15 Бюджет нижнего слоя: файл > 24 KB — «раздели по summary или сократи»; два файла, у которых ≥ 50 % фраз меньшего (тройки слов подряд) дословно есть в другом, — «назови разницу в summary или слей». Показывается, не запрещается: предел только на README сдвигал воду этажом ниже (замер на живом деле 2026-09-01: папка 79 KB за два дня). Бюджета папки нет (снят 2026-09-03): те 79 KB оказались рабочими документами — счётчик байтов не отличает deliverables от воды, а строка, которую можно закрыть только удалением хорошей работы, учит не читать `Order`. Дубликат — по дословным фразам, не по словарю: два документа об одном предмете делят имена и даты (46 % общих слов при 34 % общих фраз), копия — 80 %+.
- F16 Ссылка `[имя](путь)` ведёт на существующий файл. В README и TODO мёртвая ссылка — нарушение `check` (владелец кликает — ничего не открывается, а читает он строку `violations:`); в документах, файлах фаз и журнале — строка `Order` (в журнале считаются только цели, похожие на файл: `docs/x.md`, не `path` — история вправе привести пример, но не тупик). Файлы переносятся `el mv old new` — ссылки едут за файлом (2026-09-03); путь принимается от дела (`docs/x.md`), от корня репозитория (`.cases/<дело>/docs/x.md`, как подставляет tab-completion) и абсолютный внутри дела — канон внутри один, от дела (2026-09-16); перенесён мимо `el` — `el relink old new` переписывает ссылки, журнал включительно; удалён насовсем или ссылка была примером — `el relink old none` превращает такие ссылки в текст в обратных кавычках: слова остаются, претензия на файл уходит (2026-09-08).
- F17 Правило дела «пункт ведёт к материалу» — строка `Context` `- rule: items link their material` (`el readme add context "…"`): пока она есть, `todo add`/`edit` предупреждают о пункте без ссылки `[имя](путь)`, а `Order` называет открытые пункты без неё. Включается там, где владелец читает только README и TODO, а работа живёт в документах; в деле про код не включается (2026-09-04). Строки `State`, которые держит `el` (`progress:` на много фаз), из предела F2 на указатель исключены — их агенту не сократить.
- F18 Закон свёрнутого узла (2026-09-05, концепция `research/work-graph.md`, слом Codex). Строка узла у родителя рисуется из шапки самого узла и руками не пишется: файл — из `summary:` (F14); закрытая фаза — из `result:` (F5); открытая фаза — из `goal:` плюс путь к файлу фазы (нажал — попал в развёрнутую); вложенное дело — из `progress:` · `next:` · `closed:` ребёнка в блоке Links родителя: открытые — строкой каждое, закрытые — числом и последними пятью, полное дерево — `el case list`; ребёнок до `el` (README вне грамматики и без отпечатка) — строка `legacy` → `migrate`, ребёнок с отпечатком, который `el` больше не разбирает, — BROKEN → `check`; оба держат родителя открытым и называются каждый своим именем; в `case list` legacy-дела — одной строкой-счётом, `--all` называет каждое (2026-09-15: 28 папок до `el` дали 28 строк BROKEN и вытеснили живые дела); ребёнок при закрытии пишет родителю всегда, как бы ни был создан.
- F19 Зависимости. Суффикс пункта `— after: N.M[, N.K, имя-дела]` (перед `due` и `hold`); цель обязана существовать; циклов нет по всем рёбрам вместе (`after`, `waits`, вложенность); номер, на который ссылаются (в `after` или в журнале), не переиспользуется; при переносе пункта ссылки переписываются за ним; drop пункта, на который ссылаются, — отказ; снятый пункт зависимость не закрывает — зависимый показывается «blocked by cancelled» с двумя выходами (перевязать `todo after`, снять). На входе строка `unblocked:` — открытые пункты без открытых блокеров, по сроку и фазе; в README она не пишется, `next:` остаётся словом владельца.
- F20 Два конца у узла любого размера. Сделано — со свидетельством, у которого есть **вид** (слово владельца 2026-09-14, образец Prove2Me): `todo done N.M <вид> "что вышло"` — вид первым, список закрыт: `file:<путь>` — вещь, которую откроет любой (фото, pdf, чек, письмо, снимок экрана, транскрипт, сохранённый ответ, исходный файл кода; путь читается от папки дела, потом от корня проекта; инструмент проверяет, что файл есть, и пишет ссылку от дела; вне проекта — отказ; markdown, написанный агентом в папке дела, — его же текст со ссылкой, а не вещь: `done` предупреждает и называет, что стоит за ним — `run`, исходник или спецификация проекта, сохранённый ответ; один файл как доказательство нескольких пунктов фазы — предупреждение «артефакт каждого или один отчёт обо всех» и счёт различных доказательств в Digest; заметка, состоящая из ссылки на файл доказательства, — предупреждение с `--drop k`; всё это показ, не отказ — глаз владельца 2026-09-16 над закрытой фазой: восемь ссылок на один самописный файл) · `ref:<след снаружи>` — номер запроса, URL, письмо в почте (проверит человек вне дела; инструмент — что след назван) · `run:"<команда → исход>"` — проверка машиной (инструмент проверяет стрелку; `->` принимается и пишется `→`; значение в кавычках — без них shell читает `>` как перенаправление, отказ называет этот след) · `owner` — слово владельца, единственное слово, которое считается: агент пишет запись, поэтому его слово — не свидетельство, он оставляет файл. Фаза — `result:`, дело — итог. Снято — с причиной: `todo cancel`, `phase cancel N "почему"`, `case cancel "почему"` пишут `DECISION · снято …` и сворачивают узел в строку у родителя с пометкой «снято». Галочка снимается назад с причиной: `todo reopen N.M "почему"` — пункт снова открыт, в журнале `DECISION · N.M возвращён в работу — …`, старый `RESULT` остаётся историей. `done`/`reopen`/`cancel` берут диапазон `N.A-N.B` или список `N.A, N.B` в одной фазе — одна запись журнала называет каждый номер. Снятая в плане (не открывавшаяся) фаза возвращается в план тем же `phase plan N`: пункты возвращаются под старыми номерами, рождённый при снятии файл уходит; бежавшая фаза не возвращается — новый номер (2026-09-09). Инструмент проверяет структуру; правду о людях проверяет владелец.

При постановке — `el todo add N "…" --why "…" --note "…" --expect "…"`. Список слов закрыт (why · note · expect · result), как список видов свидетельства: пятое приходит через `el feedback` из живого дела. Пункт с четырьмя и более вопросами внутри — не пункт, а фаза или вложенное дело (P11).
