# Elephant — установка

**Elephant** — память работы агента на диске (команда называется `el`): папка `.cases/` в проекте, в ней дела с тремя файлами (README — «сейчас», TODO — фазы, JOURNAL — история). Агент пишет их только командами `el`; неправильную запись инструмент не примет и подскажет, как исправить. Инструкция agent-agnostic: подходит любому агенту (Claude Code, Codex, Gemini, Cursor …) и человеку.

## 1. Установить команду — один раз на машину

Нужен только Python 3, зависимостей нет.

```sh
git clone https://github.com/MykhailoDmytriakha/elephant-cli.git ~/MyProjects/elephant-cli   # клон может лежать где угодно
~/MyProjects/elephant-cli/install.sh        # ставит команду `el` и печатает, что делать дальше
el --version        # → elephant 1.0.0
```

Обновление на любой машине — `git pull` в клоне: команда, правила и тесты приезжают одним движением, symlink переустанавливать не нужно.

Если `command not found` — `~/.local/bin` нет в PATH; добавь в `~/.zshrc`:
```sh
export PATH="$HOME/.local/bin:$PATH"
```

## 2. Подключить проект — один раз на проект

```sh
cd <корень проекта>
el case new "название дела" --goal "цель одной строкой словами владельца"
```

Это создаст `.cases/` и первое дело. Больше ничего копировать не нужно: `el` находит `.cases/`, идя вверх от текущей папки.

## 3. Научить агента — один раз на проект

Два пути, любой работает. **Скилл** — папка `skill/` этого репозитория: скопируй её туда, где твой harness держит скиллы (Claude Code → `cp -r skill ~/.claude/skills/elephant`); скилл — только дверь, инструкция живёт в самой команде. **Текст** — вставь блок ниже в файл инструкций своего harness (Claude Code → `CLAUDE.md` · Codex → `AGENTS.md` · Gemini → `GEMINI.md` · Cursor → `.cursor/rules/` · VS Code Copilot → `.github/copilot-instructions.md`). Если ты агент и читаешь это — вставь его сам в файл, который читает твой harness, и работай по нему.

```markdown
## Elephant — память работы в .cases/
- Начинай сессию командой `el` — она печатает, где дело стоит, что дальше и блок `Order`: что не на месте и какой командой поправить. Первым сообщением перескажи своими словами, где дело стоит и что делаешь.
- README / TODO / JOURNAL дела пиши только через `el` (`el help` — примеры). Правка руками ловится отпечатком.
- Новый файл в `docs/`, `research/`, … начинай строкой `summary: <одна фраза>` под заголовком — карта в README соберётся из этих строк сама; папке дай строку `el readme add links "docs/ — что здесь"`.
- Решил что-то важное → `el log DECISION "что · вместо чего · почему"`; получил результат → `el log RESULT "…"`.
- Решил проблему → сразу `el log PROBLEM "проблема → корень → решение"` и рецепт-файл в `.howto/` (первая строка `when: <слова ошибки>`). Упёрся → сначала `grep -ril "<слова ошибки>" .howto/`.
- Закрыл кусок → `el todo done N.M "что вышло"` (это уйдёт в журнал); фазу → `el phase close N "итог"` — все её пункты должны быть сделаны или сняты; дело → `el done "итог"`. Ветка не нужна → `el phase cancel N "почему"` / `el case cancel "почему"`.
- Пункт зависит от другого → `el todo add N "текст — after: N.M"` или `el todo after N.M "N.K, имя-дела"`: на входе `el` скажет, что можно брать сейчас (`unblocked:`), а что заблокировано.
- Видишь работу со сроком вне текущей фазы → `el phase plan N "Name" --goal "…"` и `el todo add N "…"`: фаза стоит в TODO заранее, откроется `el phase open N`, когда текущая закрыта.
- У куска работы есть дата → пиши её так, чтобы инструмент видел: `el todo add N "текст — due: 2026-09-09"`; срок дела → `el readme set due "2026-09-13 · что"`. На входе `el` скажет, что сегодня, что просрочено и сколько дней до срока.
- Пункт больше не нужен → `el todo cancel N.M "почему"` (не `done`); результат отменился → `el todo reopen N.M "почему"`; пункт переехал в другую фазу → `el todo move N.M K`; переносишь файл → `el mv old new` — ссылки переписываются сами.
- Владелец читает только README и TODO → включи правило дела: `el readme add context "rule: items link their material"`. С ним `todo add` напомнит про ссылку `[имя](docs/файл.md)` в тексте пункта, а `Order` назовёт пункты без неё.
- Не знаешь причину, работа больше одной сессии или нужно решение владельца → `el spawn "имя" --goal "…"`: вложенное дело той же формы; закрыл его → `el done "итог"`, родитель получит строку сам.
- Проверить дело: `el check` (нарушения → выход 3; все дела пространства — `el check --all`); что видит Elephant отсюда: `el doctor`; как всё устроено целиком: `el help model`; Elephant ведёт себя не так → `el feedback "заголовок" --actual "…" --expected "…"`.
- Текст с `$` (суммы) пиши в одинарных кавычках: `el todo add 3 'заплатить $150'` — в двойных shell съест `$150`, а `el` откажет записывать след.
- Заканчиваешь → снова `el`: если `Order` говорит «State is behind» — перепиши `State` (`el readme set next "…"`; верен как есть — `el readme touch`; устаревшую строку убирает `el readme set <prefix> ""`). Следующая сессия начнётся с этой строки.
```

## 4. Проверить, что работает

- `el` в проекте → экран `el · case in hand: …`, выход 0
- `el` вне проекта → `no .cases/ found …`, выход 4 — так и должно быть
- `el check` → `violations: 0` (дело в руках; `el check --all` — все дела, legacy-дело там одной строкой на файл)
- `el order` → `order: ✓ everything in place` (или список того, что поправить)
- дело велось до `el` (файлы без `stamp:`) → `el migrate` покажет план, `el migrate --apply` перенесёт: старые файлы byte-for-byte в `legacy/`, новые — в грамматике

## Как это устроено — для любопытных

Форматы файлов, отпечаток и процедура описаны в `.cases/RULES.md` репозитория elephant-cli — это спецификация, по ней написаны тесты (`python3 -m unittest discover -s tests -t .`). Агенту читать её не нужно: форму держит сам инструмент, а привычки — блок из пункта 3. Коды выхода: 0 успех · 1 ошибка · 2 неверный вызов · 3 нарушение формата · 4 не выполнено условие.
