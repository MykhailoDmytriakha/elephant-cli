# Elephant — установка

**Elephant** — память работы агента на диске (команда называется `el`): папка `.cases/` в проекте, в ней дела с тремя файлами (README — «сейчас», TODO — фазы, JOURNAL — история). Агент пишет их только командами `el`; неправильную запись инструмент не примет и подскажет, как исправить. Инструкция agent-agnostic: подходит любому агенту (Claude Code, Codex, Gemini, Cursor …) и человеку.

## 1. Установить команду — один раз на машину

Нужен только Python 3, зависимостей нет.

```sh
git clone https://github.com/MykhailoDmytriakha/elephant-cli.git ~/MyProjects/elephant-cli   # клон может лежать где угодно
~/MyProjects/elephant-cli/install.sh        # ставит команду `el` и печатает, что делать дальше
el --version        # → elephant 1.12.0
```

Обновление на любой машине — `git pull` в клоне: команда, правила и тесты приезжают одним движением, symlink переустанавливать не нужно.

Если `command not found` — `~/.local/bin` нет в PATH; добавь в `~/.zshrc`:
```sh
export PATH="$HOME/.local/bin:$PATH"
```

## 2. Подключить проект — один раз на проект

```sh
cd <корень проекта>
el case new "название дела" --goal "цель одной строкой словами владельца"
```

Это создаст `.cases/` и первое дело. Больше ничего копировать не нужно: `el` находит `.cases/`, идя вверх от текущей папки.

## 3. Научить агента — один раз на проект

Открой [AGENT.md](AGENT.md), скопируй блок из-под черты и вставь в файл инструкций своего harness (Claude Code → `CLAUDE.md` · Codex → `AGENTS.md` · Gemini → `GEMINI.md` · Cursor → `.cursor/rules/` · Copilot → `.github/copilot-instructions.md`). Если ты агент и читаешь это — вставь его сам в тот файл, который читает твой harness.

Блок короткий нарочно: четыре строки и три команды. Всё остальное агент спрашивает у самого инструмента — `el` печатает состояние и `Order`, `el help start` объясняет день целиком, `el help <topic>` выдаёт знание дозами в момент нужды. Инструкции не пересказывают инструмент: он рассказывает о себе сам.

## 4. Проверить, что работает

- `el` в проекте → экран `el · case in hand: …`, выход 0
- `el` вне проекта → `no .cases/ found …`, выход 4 — так и должно быть
- `el check` → `violations: 0` (дело в руках; `el check --all` — все дела, legacy-дело там одной строкой на файл)
- `el order` → `order: ✓ everything in place` (или список того, что поправить)
- дело велось до `el` (файлы без `stamp:`) → `el migrate` покажет план, `el migrate --apply` перенесёт: старые файлы byte-for-byte в `legacy/`, новые — в грамматике

## Как это устроено — для любопытных

Форматы файлов, отпечаток и процедура описаны в `.cases/RULES.md` репозитория elephant-cli — это спецификация, по ней написаны тесты (`python3 -m unittest discover -s tests -t .`). Агенту читать её не нужно: форму держит сам инструмент, а привычки — блок из пункта 3. Коды выхода: 0 успех · 1 ошибка · 2 неверный вызов · 3 нарушение формата · 4 не выполнено условие.
