# /elephant — вход в режим

**Скилл — только дверь: вся инструкция живёт в самом CLI.** Быстрый вход без чтения файлов: запусти `el` — он представится, скажет, где дело стоит, что дальше и что не на месте (блок `Order` — по строке на беспорядок, с командой-починкой на каждой). Агент в любом harness без этого скилла получает то же самое одной командой.

Инструмент живёт в репозитории `elephant-cli` (https://github.com/MykhailoDmytriakha/elephant-cli); где лежит клон на этой машине — `readlink $(which el)`. Нет `el` — `git clone`, потом `./install.sh`.

## Порядок загрузки

1. **`el`** — экран входа: дело в руках · фаза · что можно брать сейчас · сроки · `Order`. Первым сообщением перескажи своими словами, где дело стоит и что делаешь.
2. **`el help`** — примеры всех команд одним экраном; **`el help <topic>`** — доза знания в момент нужды (темы перечислены внизу `el help`; `el help model` — как всё устроено целиком).
3. **`el check`** — дело против правил (нарушения → выход 3); **`el doctor`** — что инструмент видит отсюда, не меняя ничего.

## Привычки — пять строк

- **Пиши только через `el`.** README / TODO / JOURNAL руками не трогать: правка ловится отпечатком, и следующая запись перестроит файл по грамматике.
- **Событие в журнал в момент, когда оно случилось:** решение → `el log DECISION "что · вместо чего · почему"`, результат → `el log RESULT "…"`, решённая проблема → `el log PROBLEM "проблема → корень → решение"`.
- **Работа по пунктам:** закрыл кусок → `el todo done N.M "что вышло"`; не нужен → `el todo cancel N.M "почему"`; результат отменился → `el todo reopen N.M "почему"`. Номер пункта — на всю жизнь, ни одна команда не перенумеровывает.
- **Новый файл в `docs/`, `research/`, …** начинай строкой `summary: <одна фраза>` — карта в README соберётся сама; переносишь файл → `el mv old new`, ссылки переписываются.
- **Заканчивая сессию — снова `el`:** `Order` говорит «State is behind» → `el readme set next "…"` (верен как есть → `el readme touch`). Следующая сессия начнётся с этой строки.

## Ошибка — это адрес починки

Каждый отказ печатает код выхода и команду, которой он лечится: 0 успех · 1 ошибка · 2 неверный вызов · 3 нарушение формата · 4 не выполнено условие. Дело велось до Elephant (файлы без `stamp:`) → `el migrate` покажет план, `el migrate --apply` перенесёт. Инструмент ведёт себя не так → `el feedback "заголовок" --actual "…" --expected "…"`: отзыв ложится в `feedback/` клона и ездит с git.

## Граница

**В клоне** (ездит между машинами): команда, правила `.cases/RULES.md`, тесты, этот скилл. **В проекте** (остаётся на месте): папка `.cases/` — дела, журналы, материалы. Клон не хранит ничего про чужие дела; проект не хранит ничего про код инструмента.
