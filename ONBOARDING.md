# Блок для агента — скопируй и вставь

Ниже — всё, что нужно сказать агенту, чтобы он вёл дело этого проекта через Elephant. Скопируй текст под чертой в файл инструкций своего harness: Claude Code → `CLAUDE.md` · Codex → `AGENTS.md` · Gemini → `GEMINI.md` · Cursor → `.cursor/rules/` · Copilot → `.github/copilot-instructions.md`.

Больше подключать нечего: дальше инструмент рассказывает о себе сам — `el` печатает состояние и что поправить, `el help <topic>` выдаёт знание дозами в момент нужды.

## Elephant — память работы в `.cases/`

- Дело этого проекта ведётся командой `el`. **Начинай сессию с `el`**: она печатает, где дело стоит, что дальше и блок `Order` — что не на месте и какой командой поправить. Устройство целиком — `el help start`, дальше `el help <topic>`.
- **Пиши только через `el`**, README / TODO / JOURNAL руками не трогай — правка ловится отпечатком. Решение → `el log DECISION "что · вместо чего · почему"`; результат → `el log RESULT "…"`; сделанный пункт → `el todo done N.M <вид> "что вышло"` — вид свидетельства первым: `file:путь` · `ref:след` · `run:"команда → исход"` · `owner` (`el help evidence`).
- **Ритм — дисциплина Elephant**: сделал пункт, сразу `el todo done N.M <вид> "что вышло"`, не в конце сессии; принял решение, сразу `el log DECISION`; упёрся, сначала `grep -ril "<слова ошибки>" .howto/`, решил — `el log PROBLEM` и рецепт в `.howto/` с первой строкой `when:`. Идёшь пункт за пунктом, галочка ставится в момент, когда работа кончилась. Используешь Elephant — держишь дисциплину Elephant: запись, которой нет, для следующего агента не существует. У пункта есть карманы: `--why` (зачем), `--note` (ограничение, кого позвать, что взять, ссылка) — заполняй их словами владельца при постановке (`el help todo`).
- **Слушай подсказки.** Последняя строка вывода `hint:` — инструмент увидел в деле то, что можно сделать лучше, и назвал команду с твоим номером: сделай или скажи, почему нет. Так осваивают инструмент целиком, а не тупо. Как ведут дело сильные агенты, парами «слабо / сильно» по моментам: `el help practice`. У пункта есть карман `--expect`: напиши до работы, чем докажешь результат (`[file: …] [run: …] [owner]`), и `done` сверит принесённое с обещанным.
- **Пересказ — с избытком, приёмка — другой рукой.** Первая строка `el` — `thread:`: цель → фаза → пункт → шаг. Перескажи владельцу не его словами: что из этого следует, чего он не говорил (помечено как твой вывод), и вопросы на стыках — повтор его слов ничего не доказывает. Сделанное принимает свежая сессия по заданию `el todo brief N.M` (`el help acceptance`); что не для текущей фазы — `el todo add later "…"` (`el help later`).
- **Заканчивая — снова `el`**: если `Order` говорит «State is behind», обнови строку State (`el readme set next "…"`). Проверить дело против правил — `el check`.
- Нет команды `el` → `git clone https://github.com/MykhailoDmytriakha/elephant-cli`, затем `./elephant-cli/install.sh`.
